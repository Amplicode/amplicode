## Amplicode 2026.1.6

В этом релизе появились поддержка Spring AOP, просмотр сохранённых значений и управление временем их жизни в Connekt, а также выбор инструментов, доступных AI-агентам через MCP. В OpenIDE 2026.2 расширена интеграция с DB Client: работа с SQL и проверка соответствия сущностей схеме базы данных.

### Spring AOP

Добавлена поддержка выражений AspectJ, используемых в Spring AOP: подсветка синтаксиса, автодополнение и проверка имён. В выражениях можно переходить к пакетам, классам и методам проекта и библиотек, а также к объявленным в проекте pointcut-методам.

Поддерживаются `execution`, `this`, `target`, `@target`, `@within`, `@annotation` и `@args`.

### Connekt (HTTP-клиент)

**Просмотр и очистка сохранённых значений**

Над объявлениями переменных, значения которых сохраняются между запусками скрипта, теперь можно увидеть эти значения прямо в редакторе. Для объектов и массивов показывается ссылка `show value`, открывающая JSON в боковой вкладке; длинные строки также можно открыть целиком. Если сохранённого значения нет, отображается `empty`.

Значения можно очищать по одному через `clear` или все сразу кнопкой `Clear All Variables` на панели скрипта. Показ значений включается опцией `Enable 'Show value' inlays` в `Connekt Evaluator Settings` и по умолчанию выключен.

**Время жизни значений (TTL)**

Для сохранённого результата запроса можно задать время жизни через `ttl(...)`: фиксированное, например `ttl(5.minutes)`, или вычисляемое из тела ответа либо заголовков. Это удобно для токенов авторизации с ограниченным сроком действия: после истечения TTL следующее обращение к переменной повторно выполнит запрос и обновит значение.

При включённом показе значений устаревшее значение автоматически подсвечивается оранжевым, а подсказка объясняет, как его обновить.

**Настройка таймаутов**

Добавлены `timeout`, `connectTimeout`, `readTimeout` и `writeTimeout` с параметрами типа `Duration`. Таймаут можно задать для всего скрипта на верхнем уровне и переопределить для отдельного запроса — например, увеличить время ожидания при генерации отчёта.

**Импорт скриптов в IDEA 2026.2**

Исправлено разрешение переменных и функций из скриптов, подключённых через `@Import`: снова работают автодополнение и переход к объявлению. В меню `Troubleshooting` на панели Connekt доступно действие `Reload script configuration` для перезагрузки конфигурации скрипта.

### MCP и AI-агенты

**Выбор доступных инструментов**

На странице `Settings → Tools → Amplicode → MCP Server → Exposed Tools` можно включать и выключать отдельные инструменты или целые группы. Зависимости между инструментами учитываются автоматически. Изменения применяются без перезапуска IDE и MCP-сервера; настройка действует на всю IDE и сохраняется между запусками.

**Надёжность инструментов**

* Исправлены ошибки проверки формата ответов `get_entity_details` и `list_db_migration_files`, из-за которых агент не мог получить сведения о сущностях и миграциях.
* `run_tests` теперь запускает тесты Gradle-проектов через Gradle. Ответ содержит сводку с количеством выполненных, успешных, упавших и пропущенных тестов; если тесты не запускались, инструмент явно сообщает об этом.
* Перед выполнением инструменты дожидаются завершения импорта и индексации проекта. Это устраняет ошибки индексации и преждевременные пустые ответы о сущностях, бинах и эндпоинтах.
* Улучшены сообщения об ошибках сборки и запуска тестов. Имена параметров принимаются без учёта регистра, поддерживаются распространённые варианты имён аргументов и оба обозначения таймаута — `timeout` и `timeoutMs`.
* Время ожидания сборки через `rebuild_project` и запуска приложения через `run_runnable` по умолчанию увеличено с одной до пяти минут.

**Работа с WSL**

* Устранено зависание IDE при открытии настроек MCP Server на Windows с запущенной WSL-машиной Podman.
* Исправлена запись `config.toml` при автоматической настройке Codex в WSL.

### Работа с базами данных в OpenIDE 2026.2

Новые возможности этого раздела доступны в сборке для OpenIDE 2026.2 с DB Client версии 0.0.21 или новее.

**SQL через DB Client**

Для нативных запросов в `@Query` и SQL внутри Liquibase используются возможности DB Client: подсветка с учётом диалекта, автодополнение по реальным таблицам и колонкам, проверка их имён. Запрос из `@Query` можно открыть или выполнить в консоли DB Client.

Создание и редактирование подключений из Amplicode используют окно DB Client. При отсутствии DB Client в конфигурациях без активной подписки Ultimate сохраняется интеграция с DBeaver.

**Сверка сущностей со схемой БД**

Amplicode проверяет, соответствуют ли поля JPA- и Spring Data JDBC-сущностей таблицам и колонкам подключённой базы. Проверка учитывает стратегию именования: например, поле `createdAt` сопоставляется с колонкой `created_at`.

Если таблица или колонка отсутствует, редактор показывает предупреждение. Если в таблице есть колонки, которых ещё нет в сущности, предлагается добавить атрибуты из БД. Когда одноимённая таблица найдена в нескольких подключениях, можно выбрать нужное через быструю правку. Без подключения к БД предупреждения о несовпадении схемы не показываются.

### Connekt (HTTP-клиент)

**Компактный вывод в консоли**

Каждый HTTP-запрос и его ответ теперь группируются в единый сворачиваемый блок. По умолчанию блок свёрнут — видна только строка-заголовок: иконка состояния, метод, URL и код ответа. Состояние отображается иконкой по классу HTTP-статуса: 1xx, 2xx, 3xx, 4xx/5xx.

Заголовки запроса и ответа сворачиваются в отдельные под-блоки, тело запроса — отдельно. При выполнении use-case-скрипта с несколькими запросами каждый образует свой элемент.

![](https://storage.yandexcloud.net/amplicode-site/articles/2026-1/folding.png)

### Spring Data: AOT-метаданные для репозиториев

Функциональность работает для Spring Boot 3+ проектов.

**Inlay hints** над методами репозиториев показывают запрос, который выполнится в рантайме:

- Spring Data JPA: JPQL из AOT JSON (если данные доступны), либо вычисляется напрямую при включённой опции `alwaysShowJpaQuery`. Клик открывает меню: извлечь JPQL в аннотацию, настроить, определить Entity Graph.
- Spring Data JDBC: SQL из AOT JSON. Клик предлагает вставить запрос в `@Query`.

Если AOT-данных нет — хинт предлагает собрать проект.

**Gutter-иконки** в левом поле редактора позволяют переходить между интерфейсом репозитория и AOT-сгенерированным классом реализации (`*Impl__AotRepository`) — и обратно. Работает как для классов, так и для отдельных методов.
